🏗 Directory Architecture

The OPSX Specification Protocol (specs/)

How we organize specifications so human designers, engineers, and AI agents share an unambiguous "Living Source of Truth."

🏰 specs/main/
The Living Source of Truth

Contains the production system architecture (main.md), the roadmap (roadmap.md), and completed/ specs.

🚧 specs/changes/
Active Work-in-Progress

Every feature proposal gets a dedicated file ([feature].md). All PR design reviews happen here before coding.

🗄️ specs/archive/
Organizational Memory

Stores abandoned or rejected proposals with # Status: Rejected rationale to prevent re-litigating past decisions.

📋 Core Rule for AI Agents & Humans

Always check completed/ & archive/ first. Create specs/changes/[feature-name].md and open a PR. Do not write application code until the spec is approved by a human reviewer.

🛡️ Executable Agent Skill

The enforce-development-loop Skill: Our UX Safeguard

How our automated agent skill enforces the Product → UI/UX → Engineering development loop before any implementation code is allowed to merge.

1

Product Spec Check

Verifies product_spec.md or proposal.md exists and is tracked in roadmap.md.

2

UI/UX Implementation Spec

Verifies ui_spec.md exists and prototype code is isolated on branch next (not main).

3

Engineering Spec Check

Verifies design.md exists for backend changes and results store database schema updates.

4

Final Merge Audit Table

Generates compliance checklist table. Blocks merge if any UX or product check fails.

Step 1: Product Phase Validation

When an agent runs enforce-development-loop, it checks if specs/changes/[feature-name]/product_spec.md exists. If missing, it halts and instructs the user to draft the Product Spec first. It also checks specs/main/roadmap.md to ensure the feature is actively prioritized.

📜 UI Constitutional Contract

The UI/Style Contract (skills/style.md)

The enforceable style contract that governs all JSX markup, Tailwind classes, colors, and charts in llm-d-prism.

1. Use Primitives from src/components/ui/ Only

Buttons, Badges, Modals, Form inputs, Panels, StatCards, EmptyStates, and Spinners must come from src/components/ui/. Never re-implement inline. If a variant is missing, extend the primitive in the same PR—do not fork.

2. Colors Come From Tokens Only

No new hex literals in JSX outside ui/. Use @theme token classes (theme-bg, theme-card, --brand-accent). Chart series use CHART_SERIES / seriesColor().

3. Extract on Second Use

Any markup repeated in two places becomes a primitive (or a variant of one) in src/components/ui/ in the same PR. Never copy-paste styled JSX.

4. Strict Governance & Approvals

Changes to skills/style.md or src/components/ui/ require approval from @seanhorgan or @raji14. Enforced mechanically via .github/CODEOWNERS.

The Dashboard Production Pipeline

How we transform llm-d-benchmark reports into stunning Prism dashboards using two skills and two human review gates (specs/main/dashboard-pipeline.md).

Analyze & Design

Run skill analyze_benchmark_results.md on report YAMLs. Generates proposal.md with chart/KPI spec & endpoint shape.

🛑 GATE A (HUMAN)

Spec Approval Gate

Must be approved by @seanhorgan, @diamondburned, or @jjk-g. No application code is written until Gate A is unlocked.

STAGE 2

UI Implementation

Run skills/style.md to implement via ui/ primitives, canonical page shell, and zero new lint errors.

🛑 GATE B (HUMAN)

Implementation Gate

Must be approved by @jjk-g, @diamondburned, or @seanhorgan before merging to main/completed/.

Hard-Stop Governance: Proposed defaults in proposal.md are never self-approving. AI agents stop at Gate A automatically.

🎯 Actionable Takeaways

What This Means for Our UX Team

How UX designers lead, govern, and leverage Spec-Driven Development in daily feature iteration.

1

Lead the ui_spec.md Creation

For any feature with UI, author ui_spec.md in the change folder. Outline exactly which src/components/ui/ primitives will be used.

2

Review Proposals at Gate A

Prioritize checking the user flow and data clarity in proposal.md. If "Why" is wrong, do not let engineering proceed to "How."

3

Govern via Codeowners (@seanhorgan, @raji14)

You own skills/style.md and src/components/ui/. Never allow one-off button or card overrides in PR reviews.

4

Use AI Agents as UX Allies

Instruct AI: "Use skills/style.md to scaffold a prototype on branch next." The AI will respect your tokens automatically.
